Un prompt utile est une demande qui rend le besoin et les critères de réussite compréhensibles. Il n’a pas besoin d’une formule magique : il doit fournir les informations dont le système a besoin pour répondre correctement.

## Objectifs de la leçon

- Transformer une demande ambiguë en tâche vérifiable.
- Choisir le contexte utile sans surcharger la demande.
- Distinguer consigne de style, contrainte et preuve attendue.

## Cinq éléments pour cadrer une demande

| Élément      | Question à résoudre             | Exemple                                       |
| ------------ | ------------------------------- | --------------------------------------------- |
| Objectif     | Quel résultat voulez-vous ?     | Proposer les tests d’une fonction             |
| Contexte     | Sur quoi travaille-t-on ?       | Code, types et règles métier                  |
| Contraintes  | Quelles limites respecter ?     | Aucune dépendance nouvelle                    |
| Format       | Comment restituer le résultat ? | Tableau des scénarios et assertions           |
| Vérification | Comment juger la réponse ?      | Chaque règle couverte et hypothèses signalées |

Tous les prompts n’exigent pas ces cinq rubriques. Pour reformuler une phrase, une instruction courte peut suffire. Pour modifier un système, les contraintes et les critères deviennent essentiels.

## Un avant / après concret

Une demande comme « améliore cette API » laisse ouverts l’objectif, le périmètre et les compromis. Elle peut provoquer une réécriture inutile. Précisez d’abord le défaut observé.

```text
Objectif : la route de recherche doit rejeter une limite négative.
Contexte : voici son schéma de validation et les tests existants.
Contraintes : conserver les codes d’erreur et les conventions du projet.
Résultat : propose le changement minimal et les tests nécessaires.
Vérification : une limite négative est rejetée ; le cas valide reste inchangé.
Signale les informations qui te manquent avant de proposer une nouvelle règle.
```

Le prompt ne force pas une architecture, un validateur ou une dépendance sans lien avec le problème. Il permet de contrôler le résultat.

## Donner du contexte pertinent

Incluez les contrats, les types et les exemples nécessaires. Un fichier complet peut être utile si ses dépendances internes comptent ; sinon, un extrait ciblé facilite la lecture. Ne fournissez pas des données confidentielles simplement parce qu’elles sont disponibles.

Si vous insérez un document externe, identifiez-le comme une source à analyser. Des délimiteurs clarifient la demande, mais ne constituent pas une protection de sécurité suffisante contre des instructions malveillantes présentes dans le document.

## Utiliser une consigne de rôle avec mesure

« Explique pour un développeur débutant » précise l’audience. « Tu es un expert ayant vingt ans d’expérience » ne confère aucune expertise réelle au modèle. Les contraintes de domaine, les exemples et les vérifications apportent plus d’informations utiles qu’un curriculum vitae fictif.

Vous pouvez demander une comparaison d’options, leurs compromis et une recommandation justifiée. Demandez une justification courte fondée sur des faits observables, plutôt que l’intégralité du raisonnement interne du modèle.

## Itérer sur une preuve, pas sur une impression

Après la réponse, comparez-la aux critères initiaux. Si une règle a été oubliée, indiquez la règle et l’écart. Si le modèle invente un besoin, distinguez cette hypothèse du contrat existant. Conservez les prompts utiles avec leurs cas de test : un prompt sans exemple de réussite reste difficile à évaluer.

## Erreurs fréquentes

Évitez de cumuler des contraintes incompatibles, de demander une solution « parfaite » sans critère, ou de supposer que davantage de texte améliore toujours la réponse. Quand une information manque, autorisez une question ou une hypothèse explicite selon le risque. Une petite décision réversible n’exige pas systématiquement une interruption.

## À retenir

Un bon prompt réduit l’ambiguïté et rend le résultat vérifiable. Sa longueur importe moins que les informations qu’il apporte.
