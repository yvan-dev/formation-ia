Une hallucination est une sortie fausse ou non étayée présentée comme une réponse pertinente : API inexistante, chiffre inventé, citation incorrecte ou description qui ne correspond pas au fichier. La fluidité de la réponse ne permet pas de la détecter à elle seule.

## Objectifs de la leçon

- Reconnaître plusieurs formes d’hallucination.
- Associer chaque affirmation à une vérification appropriée.
- Réduire les erreurs sans promettre de les éliminer.

## Pourquoi une réponse plausible peut être fausse

Le modèle génère une suite adaptée à son contexte ; il n’effectue pas automatiquement une vérification factuelle. Un contexte incomplet, une API ancienne, une ambiguïté ou une récupération documentaire défaillante peuvent conduire à une réponse incorrecte.

Toutes les erreurs de code ne sont pas des hallucinations. Une règle métier mal spécifiée ou une autorisation oubliée peut produire un code valide mais inadapté. Le diagnostic doit distinguer fait inventé, incompréhension du besoin et défaut d’implémentation.

| Sortie suspecte            | Vérification utile                                           |
| -------------------------- | ------------------------------------------------------------ |
| Méthode d’une bibliothèque | Types et documentation de la version installée               |
| Statistique chiffrée       | Source primaire, date, population et méthode                 |
| Citation ou URL            | Existence de la source et passage qui soutient l’affirmation |
| Description d’un fichier   | Lecture du fichier réellement concerné                       |
| Résultat de test           | Commande exécutée, sortie et nombre de tests                 |

## Cas concret : un import proposé

Le modèle suggère une bibliothèque dont vous ne connaissez pas le nom. **Ne l’installez pas pour vérifier si elle existe.** Recherchez d’abord le package dans le registre officiel et comparez son dépôt, son éditeur et sa documentation. L’existence du nom ne prouve pas la légitimité du projet.

Un attaquant peut publier un nom de package fréquemment inventé par des modèles : ce risque est souvent appelé **slopsquatting**. Il se distingue du typosquatting, qui exploite une faute de frappe dans le nom d’un package connu. Une dépendance nouvelle demande une revue de provenance avant son exécution.

## Réduire le risque au moment du prompt

Fournissez la version utilisée, les contrats pertinents et les données réellement nécessaires. Demandez au modèle de séparer les faits observés, les hypothèses et les points à confirmer. Autorisez explicitement une réponse incomplète lorsque les sources manquent.

```text
Utilise la documentation de la version installée et les fichiers cités.
Pour chaque recommandation, indique la contrainte du projet qui la justifie.
Si la signature d’une API n’est pas vérifiée, signale-le.
Ne présente pas un test comme réussi sans l’avoir exécuté.
```

Ces instructions favorisent un comportement utile, mais ne garantissent ni leur respect ni la vérité de la réponse. Les contrôles doivent rester extérieurs au modèle.

## Vérifier avec des preuves indépendantes

Compiler un exemple peut détecter une signature inexistante, mais ne prouve pas que l’algorithme respecte le besoin. Un test nominal valide un cas, mais peut manquer une autorisation. Choisissez la preuve correspondant à l’affirmation.

Demander une autocritique ou une seconde réponse peut révéler des incohérences. Deux modèles peuvent toutefois partager la même erreur ; leur accord n’établit pas un fait. Une température basse peut réduire certaines variations, sans garantir l’exactitude, et tous les modèles n’exposent pas ce réglage.

## Réagir à une erreur

Isolez l’affirmation incorrecte, apportez la source qui la contredit et demandez une correction ciblée. Revérifiez ensuite les éléments dépendants. Si une méthode de bibliothèque est inventée, les tests et l’explication qui l’utilisent doivent aussi être revus.

## À retenir

Réduisez les occasions d’erreur avec un bon contexte, puis vérifiez les affirmations importantes avec des sources et des observations indépendantes.
