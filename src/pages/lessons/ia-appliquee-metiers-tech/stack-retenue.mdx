La stack de ce site est une référence concrète pour les exercices. Elle ne doit pas être confondue avec les applications SaaS fictives utilisées dans certains cas pédagogiques.

## Objectifs de la leçon

- Identifier les technologies réellement présentes dans le dépôt.
- Associer les scripts aux vérifications qu’ils réalisent.
- Choisir un outil IA compatible sans dépendance obligatoire à une marque.

## Le socle de l’application

**Vérification du dépôt le 4 octobre 2026.** Le site utilise Astro 5, React 19, Tailwind CSS 4 et MDX. Astro génère les pages, MDX porte les leçons, les composants partagés assurent la cohérence et Pagefind indexe les pages compilées pour la recherche.

| Élément        | Rôle dans le projet                          |
| -------------- | -------------------------------------------- |
| Astro          | Routage par fichiers et génération statique  |
| MDX            | Contenus pédagogiques et composants de leçon |
| React          | Composants interactifs lorsque nécessaires   |
| Tailwind / CSS | Styles et tokens de présentation             |
| Pagefind       | Index de recherche après build               |
| Playwright     | Vérification des parcours dans le navigateur |

Ce dépôt n’est pas une application Next.js/Express et ne possède pas le backend de notifications ou de réinitialisation présenté dans les cas fictifs. Ces exemples servent à exercer le raisonnement sur un autre contexte, clairement identifié.

## Installer selon le dépôt

Lisez le `package.json`, le lockfile et les instructions du projet. Utilisez une version de Node compatible avec les dépendances et la CI. Le lockfile décrit les versions résolues ; les plages du manifeste ne remplacent pas cette référence.

```bash
npm ci
npm run dev
```

`npm ci` utilise le lockfile et recrée l’installation. Si un script d’installation échoue, examinez sa sortie et les instructions du dépôt plutôt que d’ignorer l’erreur. Dans un environnement cloud, un script de hooks peut nécessiter un réglage documenté ; ce réglage ne doit pas masquer un échec du build.

## Vérifier le travail

```bash
npm run build
npm run lint
npm run test:e2e
```

Le build inclut la génération Astro puis l’index Pagefind. Le lint vérifie des règles de code ; il ne prouve pas que le parcours utilisateur fonctionne. Les tests E2E utilisent un navigateur et vérifient les interactions. Consultez la configuration Playwright pour son serveur et ses prérequis.

Une commande réussie avec zéro test exécuté ne constitue pas une validation du parcours. Notez le nombre de tests, les échecs et les contrôles non exécutés. Pour une modification de leçon, vérifiez aussi le rendu MDX, les liens et la navigation.

## Choisir l’assistant de développement

Vous pouvez utiliser l’outil approuvé par votre organisation, à condition de pouvoir limiter ses accès et relire ses modifications. Le cours n’exige pas un abonnement particulier. La compétence travaillée est transférable : lire, cadrer, produire, vérifier et livrer.

Si vous choisissez Claude Code, suivez sa documentation officielle. Le README recommande désormais une installation native ou un gestionnaire pris en charge ; l’installation npm y est indiquée comme dépréciée. Par exemple, avec Homebrew déjà configuré :

```bash
brew install --cask claude-code
```

Sur Windows, la documentation propose notamment WinGet. N’exécutez pas une commande d’installation copiée d’un résultat IA sans vérifier sa source. L’authentification et les conditions de données dépendent du mode d’accès choisi ; ne supposez pas qu’une clé API est toujours nécessaire ni qu’aucune donnée n’est conservée.
