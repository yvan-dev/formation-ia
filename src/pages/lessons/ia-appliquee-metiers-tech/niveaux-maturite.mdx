Une équipe peut utiliser l’IA de plusieurs façons : poser une question, recevoir une suggestion dans l’éditeur, déléguer une modification ou orchestrer un processus. Cette grille aide à discuter des pratiques et de leurs risques.

## Objectifs de la leçon

- Identifier le mode de collaboration adapté à une tâche.
- Relier autonomie, permissions et supervision.
- Fixer un objectif de progression observable.

## Une grille pédagogique, pas une certification

Les cinq niveaux ci-dessous constituent le vocabulaire de ce parcours. Ils ne sont ni une norme industrielle, ni un classement scientifique. Ils peuvent coexister dans une même équipe et sur un même projet.

Le niveau le plus autonome n’est pas nécessairement le plus pertinent. Pour une question de conception, une conversation peut suffire ; pour une modification répétitive bien spécifiée, un agent peut réduire le travail manuel. La supervision humaine traverse tous les niveaux.

| Mode                      | Ce que l’IA fait                               | Ce que vous devez contrôler                      |
| ------------------------- | ---------------------------------------------- | ------------------------------------------------ |
| **1 · Chat**              | Propose une explication ou un brouillon        | Sources, contexte, exactitude                    |
| **2 · Copilote**          | Suggère du code au sein de votre travail       | Diff, conventions, tests ciblés                  |
| **3 · Agent guidé**       | Enchaîne lecture, modification et vérification | Objectif, outils, périmètre, résultat            |
| **4 · Human in the Loop** | Exécute un workflow avec points de décision    | Action concrète, arguments, reprise et refus     |
| **5 · Swarm**             | Coordonne plusieurs agents spécialisés         | Responsabilités, conflits, budget, observabilité |

## Passer d’un mode à l’autre

Une progression utile commence par la stabilisation d’un usage simple. Si les critères de réussite sont flous, ajouter des agents ne les rendra pas plus clairs. Si un test ne vérifie pas le bon comportement, automatiser son exécution ne corrige pas ce défaut.

Pour passer au mode agent guidé, choisissez une tâche bornée, par exemple compléter une documentation à partir de fonctions existantes. Définissez les fichiers modifiables, les commandes nécessaires, les critères de réussite et les conditions d’arrêt. Commencez avec les permissions minimales. Le contrôle d’accès doit être appliqué par l’environnement, pas uniquement demandé dans un texte.

## Cas concret : modifier une page de formation

Vous voulez corriger une légende et vérifier sa lisibilité sur mobile. Un copilote peut suggérer le texte ; un agent guidé peut modifier le fichier et lancer le build. Il n’a pas besoin de secrets, de données clients ou d’un accès de déploiement.

Pour publier la modification, votre processus peut imposer une revue humaine de la PR. Cette décision est distincte de la création de la PR, qui peut déjà être autorisée par la demande. Ne multipliez pas les confirmations pour les actions réversibles prévues dans la mission : réservez les points de décision aux actions sensibles et aux ambiguïtés bloquantes.

## Mesurer une progression réelle

Choisissez une mesure liée à la qualité : proportion de tâches acceptées après revue, erreurs détectées, temps total avec corrections, changements hors périmètre ou incidents. Un volume de prompts ou de lignes générées ne mesure pas directement une amélioration.

Comparez des tâches de difficulté similaire, avec et sans assistance, et notez les conditions de l’essai. Un gain sur une documentation ne prouve pas un gain sur une migration de données.

## À retenir

La maturité consiste à choisir l’autonomie adaptée et à vérifier les résultats. Elle ne se mesure pas au nombre d’agents déployés.
